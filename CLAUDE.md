# CLAUDE.md

## Overview

Garap - A web-app for managing multiple tasks with multiple categories and boards. Simpler version of Google Keep and Trello.

## ⚠️ Architectural Changes — MUST Write an ADR

**Any architectural change requires a new ADR in `docs/adr/` BEFORE or ALONGSIDE the code change. Non-negotiable.**

### What counts as architectural

- Adding/removing/replacing a library or framework (e.g. swap Dexie, add Zustand, drop TanStack Router).
- Changing module boundaries (`src/modules/*`) — splitting, merging, renaming, adding new module.
- Changing the data model (`Board`, `Card`, `Item`, `TodayRef`, `WeekRef` shapes; new stores).
- Changing persistence strategy (IndexedDB → File System API, adding sync, adding backend).
- Changing layer rules / dependency direction.
- Changing the testing strategy (what gets tested, with what tool, at what layer).
- Changing deployment target, build tool, or error-reporting strategy.
- Adding auth, networking, multi-device, or any server component.

### What does NOT count (no ADR needed)

- Adding a new component, hook, or route inside existing structure.
- Bug fixes, refactors that preserve interfaces.
- Styling, copy changes.
- Adding tests within established conventions.
- Adding a new function inside an existing module.

### How to write an ADR

1. Filename: `docs/adr/NNNN-kebab-case-title.md` — `NNNN` is next sequential number (zero-padded, 4 digits).
2. Follow the template of `0001-client-only-local-first-architecture.md`:
   - **Status** (Proposed | Accepted | Superseded by ADR-XXXX | Deprecated)
   - **Date** (ISO `YYYY-MM-DD`)
   - **Deciders**
   - **Context** (why now, constraints, alternatives considered)
   - **Decision** (what was chosen, concretely)
   - **Consequences** (positive, negative, revisit triggers)
3. If superseding an old ADR, set the old one's status to `Superseded by ADR-NNNN` (do not delete).
4. Commit the ADR in the same PR as the code change. Commit message scope: `docs(adr): ...`.

**If you change architecture without writing an ADR, you have not finished the change.**

## Tech Stack

- React 19 + TypeScript + Vite
- TanStack Router for routing
- Dexie.js for wrapping IndexedDB
- dexie-react-hooks (useLiveQuery) for reactive data - no Zustand (Dexie hooks cover reactivity; UI state stays local or in URL)
- shadcn/ui (Tailwind + Radix primitives) for components (Dialog, Tabs, Tooltip, Button)
- Testing: Vitest + React Testing Library + Playwright (E2E)
- Deploy: Netlify (static SPA, auto-deploy on push)

### Layer rules

- `routes/` → import `hooks/` + `components/`. Never `modules/` directly.
- `components/` → import other components + `hooks/`. Never Dexie, never `modules/db`.
- `hooks/` → import `modules/*`. Wrap `useLiveQuery` + module ops.
- `modules/` → import other `modules/` only when needed. Never import React.
- `lib/` → leaf utils. No app imports.

Dependency direction: `routes → components → hooks → modules → lib` (one-way).

### Test placement

| Location | Tool | Why |
|----------|------|-----|
| `src/modules/*/__tests__/` | Vitest | Business logic — full coverage |
| `src/lib/__tests__/date.test.ts` | Vitest | Date math bug-prone |
| `e2e/` | Playwright | Golden paths |
| `components/`, `hooks/`, `routes/` | — | No logic → no tests |

## Code Conventions

### File Naming

- **All files and directories: `kebab-case`** — `board-card.tsx`, `use-boards.ts`, `set-completed.ts`, `inline-edit.tsx`, `list-refs/`, `auto-clear/`.
- Exceptions: framework-required names stay as-is — `__root.tsx`, `board.$boardId.tsx` (TanStack Router), `routeTree.gen.ts` (generated), config files (`vite.config.ts`, etc.).
- Test files: `<name>.test.ts` mirroring source (`set-completed.test.ts`).
- Symbols inside files keep their idiomatic case: components `PascalCase`, hooks `camelCase` (`useBoards`), types `PascalCase`.

### Commit Messages — Conventional Commits

Format: `<type>(<scope>)?: <subject>`

**Types:**
- `feat` — new feature
- `fix` — bug fix
- `refactor` — code change, no behavior change
- `docs` — docs only
- `test` — test only
- `chore` — tooling, deps, config
- `style` — formatting, no logic
- `perf` — performance fix

**Rules:**
- Subject ≤50 chars, imperative mood ("add", not "added"/"adds"), lowercase, no trailing period.
- Scope optional, matches module/area (`feat(auto-clear): ...`, `fix(db): ...`).
- Body only when "why" not obvious from subject. Wrap at 72 chars.
- Breaking change: `feat!: ...` or footer `BREAKING CHANGE: ...`.

**Examples:**
```
feat(auto-clear): add Monday boundary detection
fix(db): cascade delete cards when board deleted
refactor(list-refs): extract dedup helper
docs: add file structure to CLAUDE.md
test(boundaries): cover DST spring-forward case
```
